# 아키텍처 · 장면 구성

## 구조

```
shared/            클라이언트·서버 공용 (순수 TypeScript, 단위 테스트 대상)
  types.ts         평가 JSON 구조 (concept/reasoning/application_score, level, recommended_action …)
  curriculum.ts    핵심 개념 6개, 질문(게임·D+0·D+1·D+3), 오개념, 힌트, 데모 예시 답변, 빈칸 정리
  scoring.ts       말더듬·간투사 정규화, 데모 채점, 수준(level)·다음 행동(action) 결정
  flow.ts          미션 정의와 분기 규칙 decideNext() — A/B/C 경로
  review.ts        D+0/D+1/D+3 일정(학생 기기의 현지 날짜 기준)
  progress.ts      학생별 학습 기록 모델 + 갱신 함수
server/            Node API (node:http, 의존성 최소)
  index.ts         /api/assess, /api/push/*, /api/health, 배포 시 dist 정적 제공, IP별 요청 제한
  ai.ts            Claude 구조화 출력 채점 → 수준/분기는 shared 규칙으로 결정 (AI 실패 시 데모 채점 + 사유 표시)
  push.ts          Web Push 구독 저장·예약 발송(1분 주기), 만료 구독 정리
src/
  game/world.ts    혈관 구간 10개: 3D 곡선 + 2D 지도 경로 + 산소량 + 갈림길 정의 (같은 ID 공유 → 위치 동기화)
  game/runtime.ts  매 프레임 값(탐사선·입력·심박)은 가변 객체 — React 리렌더 없음
  game/Scene.tsx   이동·카메라·트리거 Director, 갈림길 포털, 조명/안개/입자, 품질별 Bloom
  game/Circulation.tsx  가변 반지름 튜브(심방·심실 부풂) + 흐름 무늬 셰이더, 적혈구(오목 원반) 인스턴싱, 판막
  game/Organs.tsx  박동하는 심장(변형 구), 숨쉬는 허파꽈리, 수축하는 근육, O₂/CO₂ 교환 입자
  store/useGame.ts 진행 상태 머신 (intro → travel → gate → cinematic → question → feedback → lab/scaffold → ending)
  store/progressRepo.ts  ProgressRepository 인터페이스 + localStorage 구현 (서버 저장소로 교체 가능)
  ui/*             지도, 답변/피드백, 실험실, 복습, 메인/기록
```

3D 자산은 모두 코드로 생성했습니다. `world.ts`의 곡선과 `Organs.tsx`의 메시를 glTF 모델로 바꿔도 진행·지도·트리거 로직은 그대로 동작합니다(구간 ID와 위치 t만 사용).

## 순환 경로 (지도·3D 공통)

좌심실 → 대동맥 → 근육 모세혈관(온몸) → 대정맥 → 우심방 → 우심실 → 폐동맥 → 폐 모세혈관 → 폐정맥 → 좌심방 → 좌심실

지도에서 **색 = 산소량**(빨강 많음 / 보라 적음), **선 모양 = 동맥(실선: 심장에서 나감) / 정맥(점선: 심장으로 들어옴)** 으로 분리했습니다. 폐동맥은 "보라색 실선", 폐정맥은 "빨간 점선"이라 '동맥 = 산소 많은 혈액' 오개념이 생기지 않으며, 두 구간을 지날 때 모든 학생에게 안내 대사가 나옵니다.

## 에피소드 흐름

| 단계 | 장소 | 내용 | 분기 |
|---|---|---|---|
| 도입 | 다리 정맥 | 루미 등장, "근육에 산소가 부족!" | – |
| 미션 1 | 우심방·우심실 갈림길 2곳 | 혈액이 갈 길을 직접 선택 | 오답 1회: 관찰 힌트 + 적혈구 흐름 표시 / 2회: 정답 쪽 강조. 오답 3회 이상이면 다음 질문을 쉬운 버전부터 |
| 미션 2 | 폐동맥 입구 | 박동하는 심장 관찰(관찰 모드) → 심장의 역할 설명 | A/B/C |
| 미션 3 | 폐 모세혈관 | 적혈구 색 변화, O₂·CO₂ 교환 관찰 → 혈액과 폐 연결 설명 | A/B/C |
| 미션 4 | 근육으로 순간 이동 | 달리기 시작, 심박 72→150 → 이유 추리 | A/B (+ 잘하면 추가 질문) |
| 최종 | 새 사건 | 높은 산(산소 적은 공기) — 이전 답 반복으로는 못 푸는 응용. 수준별로 쉬운/보통/심화(운동선수 심박) | – |

### 학생 수준별 분기 (shared/flow.ts)

- **A 탐색 중(beginner)**: 1차 → 힌트(정답 비공개) + 더 쉬운 질문 / 2차 → 재관찰 실험실(펌프·산소 배달·달리기 실험) 후 재도전 / 3차 → 빈칸 정리 후 진행. 벌점 없음, 막히지 않음.
- **B 기본 이해(intermediate)**: 진행. 이유 설명이 약하면 '왜' 추가 질문 1회.
- **C 깊은 이해(advanced)**: 심화 사건(판막 고장 경보, 폐동맥 이름 사건) 또는 한 단계 깊은 질문.
- 수준은 답변마다 최근 결과에 가중치를 두어 갱신되고 다음 미션의 첫 질문 난도를 정합니다. 모든 경로가 각 미션의 쉬운/기본 질문과 실험실을 거치므로 핵심 개념은 모두 다룹니다.

## AI 구술 평가

1. 음성 → Web Speech API(ko-KR, 연속 인식) → 텍스트. 녹음 파일은 만들지도 저장하지도 않습니다. 인식 불가 환경은 글자 입력.
2. `POST /api/assess {questionId, answer, attempt, branches}` → 서버가 Claude에 질문·의미 기준·개념 정의·오개념 목록과 학생 답(`<student_answer>` 태그, 지시 무시)을 보내 구조화 JSON(점수 3개, 맞은/빠진 개념, 오개념, 힌트 질문, 피드백)을 받습니다.
3. **수준과 분기(level, recommended_action)는 AI가 아니라 공용 규칙이 결정**합니다 → AI·데모 모드가 같은 진행 규칙을 따르고 결과가 일관됩니다.
4. 키가 없거나 AI 호출이 실패하면 데모 채점(규칙 기반)으로 대체하고, 화면과 JSON(`source: "demo"`, `fallback_reason`)에 그 사실을 표시합니다.

데모 채점은 개념마다 여러 표현을 받는 의미 패턴(예: "펌프/꽉 짜서/쥐어짜듯/밀어서 보내")과 원인 연결어로 점수를 매기며, 말더듬·간투사·띄어쓰기를 지운 뒤 비교합니다. 그래도 규칙 기반이라 예상 못 한 표현은 놓칠 수 있습니다 — 실제 수업에는 AI 채점을 권장합니다.

## 저장 · 개인정보

- 학생 식별: 기기에서 만든 무작위 ID + 별명(실명 불필요). 학습 기록은 브라우저 localStorage에만 저장.
- 서버는 답변 내용을 로그에 남기지 않습니다. 알림 구독은 무작위 ID로만 저장.
- 다수 학생 확장: `ProgressRepository`를 서버 API 구현으로 교체하면 됩니다. 진행 로직(`shared/*`)은 학생별 상태만 받는 순수 함수라 동시 접속에서도 각자 다른 난도로 진행됩니다.

## 복습

완료 시각 기준 D+0(즉시), D+1·D+3(해당 날짜 0시부터 가능, 알림은 16시). 단계마다 다른 질문 3개(약 3~5분). D+3은 처음 보는 사건(좁아진 다리 혈관, 숨 참기 후 몰아쉬기, 줄넘기 후 회복)에 여러 개념을 연결해야 합니다. 앱을 다시 열면 메인에 "오늘의 복습 미션 도착!"이 자동 표시되고, 완료하면 이해도 변화 그래프가 갱신됩니다.

## 그래픽 품질 · 오류 복구

- 품질 낮음/보통/높음: 해상도 배율, 적혈구 수, 튜브 분할, 허파꽈리 수, 입자 수, Bloom. 처음엔 기기 성능(코어·메모리·터치)으로 자동 선택.
- WebGL 미지원 / 렌더링 예외 / 그래픽 컨텍스트 손실 → 2.5초간 브라우저 복구를 기다린 뒤 안내 화면("다시 시도", "낮은 화질로 다시 시도"). 진행 상태는 유지됩니다.
