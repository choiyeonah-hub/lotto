# CODEX 마스터 개발 프롬프트
## 프로젝트: 나를 찾는 추억여행 by1998

너는 수석 게임 프로그래머, 3D 테크니컬 아티스트, 인터랙션 디자이너, 웹 풀스택 엔지니어, 접근성/개인정보 설계 담당자다. 지금부터 **아이디어 문서가 아니라 직접 조작하고 실행할 수 있는 3D 웹앱**을 이 저장소에 구축하라. 계획만 설명하고 멈추지 말고, 코드를 생성·실행·검증하라.

# 0. 절대로 혼동하지 말아야 할 프로젝트 정체성
- 정식 프로젝트명/브랜드: **나를 찾는 추억여행 by1998**.
- 전체 콘셉트: 사용자가 1998년 한국의 동네로 시간여행하여 당시의 방·골목·문방구·음악·물건·놀이를 경험하며, 어린 시절의 자신과 현재의 자신을 발견하는 **따뜻하고 세밀한 3D 가상 안식처**.
- **‘나답다’**는 전체 세계 안에 있는 ‘어린 나를 다시 만나고 돌보는’ 자기발견 경험/스토리 축이다. 전체 앱의 유일한 이름이나 유일한 기능으로 대체하지 마라.
- **고무줄놀이는 많은 놀이 중 첫 번째 구현할 미니게임**이다. 앱 전체를 고무줄놀이 서비스로 만들지 마라.
- 경쟁·등급·탈락·좋아요 수·친구 수 비교·일일 접속 압박·유료 보상 강요를 도입하지 마라.
- 이 세계의 핵심 문장: **“너다운 게 가장 좋아. 아무것도 잘하지 못해도 너는 소중한 사람이야.”**
- 핵심 루프: **놀이가 기억을 깨우고 → 기억이 대화로 이어지고 → 대화가 물건에 남는다.**
- '치료'나 '진단'을 약속하지 말고, 휴식·자기돌봄·기억 탐색을 돕는 체험으로 포지셔닝하라.

# 1. 처음 켰을 때 반드시 보이는 경험
1) 로딩 이후 3D 타이틀/시작 화면에 브랜드 ‘나를 찾는 추억여행 by1998’와 ‘1998년, 나의 동네로 돌아가다’ 표시.
2) 클릭/터치하면 1998년 한국의 작은 주택가 골목을 3D로 보여준다. 카메라·깊이·조명·그림자가 있는 진짜 3D 씬. 단순한 이미지, CSS 원근 카드, SVG, 정지영상, 정적 UI를 3D라고 부르지 마라.
3) 플레이어 캐릭터가 키보드 WASD/방향키 및 모바일 가상 조이스틱으로 골목을 걸어 다니고, 카메라가 따라간다. 마우스/터치로 시점을 움직일 수 있다.
4) 집 문으로 들어가면 1998년의 나의 방으로 전환된다. 문방구로 가면 당시 물건을 구경·선택한다. 운동장/공터로 가면 고무줄놀이로 이동한다.
5) 모든 방문·상호작용은 실제 공간 내 위치와 오브젝트로 연결한다. 스크린마다 텍스트 카드만 바뀌는 메뉴 모음이 되면 실패다.

# 2. 미술 방향: 진짜 1998년 한국, 따뜻한 현실감
- 전반적으로 **따뜻하고 사실감 있는 고품질 stylized 3D**. 과장된 유아용 SD 캐릭터나 저품질 원시 도형 덩어리 같은 느낌 금지.
- 골목: 1990년대 말 한국의 저층 주택/연립주택, 대문, 콘크리트 담, 전봇대와 전선, 낡은 보도블록·아스팔트, 문방구, 작은 공터, 화분, 간판, 노을, 실내 창빛.
- 개인방: 나무 책상·의자, 서랍, 철제 책꽂이, 꽃무늬 커튼, 카세트/워크맨, 브라운관 TV, 플로피 디스크 시대 컴퓨터, 일기장, 학용품, 인형, 사진액자, 침구, 동네 문방구에서 산 듯한 추억 소품.
- 사용자가 당시 **실제로 가졌던 방** 또는 **그때 갖고 싶었던 방**을 만들 수 있도록 한다. '내 방이 없었다'는 응답도 자연스럽게 지원.
- 1998년에 실재했을 법한 모델/소품부터 채택하고, 실제 브랜드·로고·캐릭터·포장/앨범 아트 재현은 권리 확인 후 사용한다. 초기에는 시대 고증이 맞는 오리지널 모델을 사용하고, 추후 초코파이·메로나 등 브랜드와 제휴할 수 있도록 아이템 데이터/에셋 라이선스 구조를 마련한다.
- 첫 소품은 무료로 제공하고, 꾸미기를 심리적 회복의 유료 조건으로 만들지 않는다.
- day/night, 비 오는 날, 창문 빛·실내 조명, 빗소리와 골목 생활음을 선택 가능하게. 소리는 기본 무음/낮은 음량도 지원.
- 품질을 위해 그림자, PBR 재질, 텍스처, LOD, 거리별 로딩, 모바일 폴백을 사용한다. 외부 3D 에셋은 라이선스와 출처를 명시한다.

# 3. 3D 캐릭터: 현재의 나와 어린 나
- 사용자는 **어린 시절 본인 사진 또는 현재의 사진을 직접 올려** 자신을 닮은 어린 캐릭터를 생성/수정할 수 있다. 사진을 올리지 않아도 기본 아바타로 즉시 이용할 수 있다.
- 사진 기반 생성에는 업로드 전 동의, 목적 설명, 보관기간, 삭제 기능을 제공한다. 사진을 공개 골목/다른 사용자에게 임의로 전송하지 않는다.
- 이미지 생성 서버나 API 키가 없는 환경에서는 조작 가능한 일반 아바타 편집기를 실제 동작시키고, 사진→3D 아바타 변환은 `AvatarGenerationAdapter`와 명백한 ‘연결 필요’ 상태로 분리한다. 업로드만 받고 생성한 척하지 말라.
- 몸체는 실제 관절 계층 또는 리깅된 GLB 아바타: 골반·척추·어깨·팔꿈치·손·무릎·발목·목이 움직여야 한다. 최소한 걷기/달리기/대기/점프/착지/줄 밟기/줄 걸기/몸 돌리기/앉기/손 흔들기의 상태 기반 애니메이션을 제공한다.
- 카메라 follow와 오클루전 처리, 땅/벽 충돌, 보행 속도, 방향 전환, 발이 바닥에 붙는 느낌을 구현한다. 허수아비처럼 정지하거나 화면만 흔들리는 연출은 불합격이다.

# 4. 세계의 3단계 변화: 순위가 아닌 자기발견
1. **기억의 방**: 조용하고 비어 있는 방. 사용자는 어릴 적 실제 물건/갖고 싶었던 물건을 찾아 배치하며 자신의 취향을 기억한다.
2. **관심이 쌓이는 방**: 사용자에게 소중한 물건·음악·대화·스스로에게 해준 말이 차곡차곡 남고 어린 나의 움직임과 표현이 풍부해진다.
3. **나다운 세계**: 집 밖 정원·동네·새로운 공간으로 확장되며 사용자 스스로 선택한다.
- 이 단계는 필수 미션과 고득점으로 강제 해금하지 않는다. 언제든 쉬고 둘러볼 수 있고 사용자가 직접 확장하도록 한다.
- 어릴 적 부정적 경험을 반드시 고백해야 한다는 진입장벽 금지. 과거가 불편한 사용자는 상상 속 방으로 바로 시작할 수 있다.

# 5. 추억 물건과 음악
- 실제 1990년대의 생활 물건을 고를 수 있는 **문방구/물건 카탈로그**를 만들고, 각 물건에 출시시대(확실할 때만), 분류, 설명, 3D 에셋 경로, 권리 상태, 소유/기억 메모, 저장된 목소리/문구 필드를 둔다.
- 소품은 실제로 방에 배치/회전/이동/저장 가능. 카드 클릭만으로 '배치됨' 텍스트가 뜨는 게 아니라 3D 방 안에 오브젝트가 렌더링돼야 한다.
- 카세트 플레이어/워크맨 오브젝트를 클릭하면 실제 아티스트·곡을 선택할 수 있다. 예: 토이, 서태지와 아이들, H.O.T. (각 곡 발매연도/표기 검증). 사용자는 자기 시대를 대표하는 곡을 더 추가 가능.
- 음원 파일을 불법 복제·내장·무단 스트리밍하지 않는다. 서비스별 정책과 음악 권리 조건에 맞는 공식 플레이어/외부 앱 링크로 연결한다. 실제 곡을 재생할 권리가 없다면 제목/가수 선택과 메모 및 합법적인 서비스로 이동하는 기능을 구현한다. 무권리 커버곡/가짜 원곡 재생 금지.
- 라이선스 확보된 오리지널 배경음/환경음은 앱 내부에 포함 가능. 각 물건에 글·사용자가 직접 녹음한 말·AI 대화에서 사용자가 선택한 문장을 연결할 수 있다.

# 6. 핵심: AI가 처음부터 '나를 알아가는' 대화
- 온보딩은 부드럽고 호기심 어린 AI 동반자 대화로 진행한다. 단, 상담 자격을 갖춘 치료사라고 사칭하지 않는다.
- 예시: “어릴 때 어떤 공간에서 시간을 보내는 게 좋았어?”, “그때 갖고 싶었던 물건이 있어?”, “누군가 널 어떻게 대해주면 좋았을까?”, “작은 나에게 오늘 어떤 말을 해주고 싶어?”
- 사용자는 건너뛰기·짧은 선택지·자유 입력·음성 입력 중 편한 방식으로 답한다. 아픈 기억을 반드시 요구하지 않는다.
- AI는 사용자가 직접 말한 취향/기억/듣고 싶었던 말을 **사용자의 확인을 거쳐** 구조화한다. 예: `favorite_music`, `memory_objects`, `preferred_play`, `wanted_words`, `comfort_preferences`, `topics_to_avoid`.
- 인격 유형·트라우마·애착 유형을 임의 진단하지 않는다. 정보는 편집/삭제 가능한 형태로 보관하며, 사적인 내용은 공개 공간/매칭에 사용하지 않는다.
- 대화 흐름: (a) 공감/인정 → (b) 판단 없는 질문 하나 → (c) 사용자가 어린 나에게 직접 하고 싶은 말 만들기 → (d) 그 말이 지금의 자신에게도 필요한지 선택적으로 되묻기 → (e) 선택한 물건에 문장/자기 목소리를 저장.
- 기분이 좋으면 즐거움을 나누고, 기분이 좋지 않으면 속도를 늦추며, 아무 말도 싫으면 조용히 끝내도록 한다. '무조건 긍정하라'는 강요 금지.
- 예시 대화:
  AI: “오늘 고무줄놀이 어땠어?”
  사용자: “어렸을 땐 끼고 싶어도 못 끼었어.”
  AI: “그때 같이 놀고 싶었겠구나. 지금 그 아이에게 어떤 말을 해주고 싶어?”
  사용자: “너도 함께 놀 자격이 있어. 잘 못해도 괜찮아.”
  AI: “이 말을 고무줄 상자에 남길까? 지금의 너에게도 듣고 싶은 말일까?”
- LLM API 설정이 없을 때도 기본 대화 트리/규칙 기반 대체 모드가 **실제로 동작**하게 구현한다. API 연결 안 된 기능을 동작하는 것처럼 숨기지 않는다.
- 안전: 위기 언급 시 임의 치료나 위험한 조언 대신 긴급 도움 선택지를 제공하는 가드레일; 사적 텍스트 최소수집, 기본 로컬 저장, 서버 전송 전 분명한 동의.

# 7. 1998년 골목의 놀이들
- '고무줄놀이'를 첫 번째 완전 동작 미니게임으로 만든다. 향후 '땅따먹기', '팽이치기', '구슬치기', '공기놀이', '딱지치기'를 동일한 플러그인 인터페이스로 추가 가능하게 설계한다.
- 게임은 추억과 휴식이 핵심이다. 실패/실수에 대한 모욕, 탈락, 경쟁 랭킹은 없다. 조작을 즐기는 사람에게는 실제 미니게임 실력이 보이되, 수치로 자기 가치를 평가하지 않는다.
- 다른 사람과 놀이한 뒤 돌아오면 조용히 개인방에서 AI와 감정을 이야기할 수 있다. 상대방과의 공개 대화 내역은 추출하지 않는다.

# 8. 고무줄놀이 — 이전 시연 실패를 교정하는 절대 조건
**과거 시연의 실패: SVG 인물 아이콘/간단한 선과 단계별 텍스트만 바뀌었고, 실제 3D 캐릭터가 움직이지 않았다. 절대로 같은 결과물을 만들지 마라.**

**반드시 작동할 플레이 가능한 3D 장면:**
- 1998년 골목 안에 3명의 3D 캐릭터: 플레이어 어린 나 1명, 고무줄을 잡는 친구 2명(NPC 또는 실제 사용자).
- 두 잡는 사람 사이에 실제로 보이는 **긴 고무줄의 두 가닥**을 3D 월드 좌표에 설치. 발목 높이에서 시작한다. 캐릭터/발 접촉에 따라 고무줄이 변위·당겨짐·복원되는 시각 효과가 나타나야 한다. Three.js Curve/TubeGeometry/라인 및 단순 rope simulation/IK 등을 활용해도 된다.
- 플레이어는 WASD/방향키로 **3D 공간에서 실제 이동**하고, Space로 **실제 점프 애니메이션**을 실행하며 Y좌표/골반/발이 움직여 줄을 넘는다. 전진/뒤로 걷기·회전·착지 동작이 연속적이어야 한다.
- 모바일은 화면의 가상 조이스틱 + '점프', '밟기', '걸기', '돌기' 터치 컨트롤을 제공한다. PC도 J=밟기, K=걸기, L=돌기 등을 제공한다.
- 줄 밟기: 발이 줄에 닿는 순간 줄이 아래로 눌리는 모습. 줄 걸기: 발에 잠깐 걸린 채 팽팽해지는 모습. 돌기: 캐릭터 방향·다리 포즈가 실제로 바뀌는 모습. 점프: 발이 줄을 건너고 자연스럽게 착지.
- 최소 4동작 시퀀스 **접근 → 넘기(점프) → 밟기 → 걸고 돌기 → 놓고 착지**를 실제 애니메이션과 위치 변경으로 완주하게 구현한다. 텍스트 버튼만 다음 단계로 넘어가는 모형은 불합격.
- 물리엔진을 쓴다면 @react-three/rapier 또는 대체 방식; 본질은 사용자 조작에 반응하는 일관된 동작·충돌·줄 변형이다. 애니메이션/접촉은 자동 데모가 아니라 입력에 따라 변해야 한다.
- 실패하면 아이가 가볍게 균형을 잡고 다시 시작할 수 있다. 탈락/점수 감점/친구의 비난 금지.
- 줄 높이(발목→종아리→무릎 등), 지역별 고무줄놀이 변형과 리듬을 추후 추가할 수 있게 데이터 중심 설계. 1990년대 실제 노랫말·음원을 무단으로 가져오지 말고 오리지널 박자/합법적 음원 사용.
- 플레이어 시점(3인칭)과 카메라 오빗, 그림자, 바닥과 줄 사이의 실제 높낮이, 3D 아바타의 걷기/점프 애니메이션이 육안으로 확인되어야 한다.
- 가능하면 Playwright 브라우저 E2E로 `게임 입장 → WASD → Space → J/K/L → 캐릭터 위치/애니메이션 상태/고무줄 변형 관찰 → 놀이 종료`를 자동으로 검증하라. 3D 렌더링이 정지하면 성공 처리하지 마라.

# 9. 낯선 사람과도 함께 놀기
- 공개 골목은 선택적으로 참여하는 공간. 놀이 선택을 기준으로 최대 3~4명이 같은 방에 입장 가능하게 설계한다.
- 참가자가 모자라면 **NPC라고 분명히 표시한** AI 친구가 줄을 잡아주고, 사용자는 혼자서도 놀 수 있다.
- 친구 초대 링크로 비공개 골목 생성 가능. 익명 사용자 공개 매칭은 백엔드/정책/모더레이션/차단 시스템이 준비된 뒤 실제로 구현한다. **가짜 이용자를 실제 사람인 것처럼 표시하지 않는다.**
- 처음에는 채팅 없이 정해진 손짓(손 흔들기, 함께 놀자, 고마워, 잘했어)만 제공. 경쟁, 모욕, 집단배제, 개인 연락처 공유 유도 금지.
- 개인방과 AI 대화/사진/음성은 절대 타인에게 노출되지 않는다. 매칭에는 놀이 종류·공개 참여 의사만 사용한다.
- 연령별 안전: 미성년자와 성인의 무작위 매칭 금지, 신고·차단·세션 나가기, 간단한 모더레이션, 개인정보 최소화. 초기 공개 매칭은 성인 대상으로 제한하거나 구현 전까지 비활성화한다.
- 공유 공간에서 익명으로 함께 놀되, 친구가 없다는 이유로 벌점·고립감을 주는 메시지를 띄우지 마라.

# 10. 나답다 경험은 놀이에 종속되지 않는다
- 집/방에 있을 때 어린 나는 사용자를 재촉하지 않고 자연스럽게 움직인다. 사용자는 그냥 앉아서 음악을 듣고, 편지를 쓰고, 좋아하는 물건을 고르거나 조용히 창밖을 바라볼 수 있다.
- '오늘 아무것도 하지 않았어도 괜찮아', '너다운 것이 좋아' 같은 말은 **사용자가 원할 때**, 특히 물건에 직접 담아 둔 자기 언어로 다시 들을 수 있다.
- 잠금화면 꾸미기는 제품 핵심이 아니다. 부가적인 알림이나 위젯에 지나치게 개발 자원을 쓰지 마라.
- '어린 나'가 며칠 접속하지 않았다고 외로움/슬픔/벌을 표현하거나 사용자에게 죄책감을 주지 않게 하라.
- 사용자의 기록이 쌓일수록 3D 방 물건과 어린 나의 행동이 조금씩 자연스럽게 풍성해지지만, 강제 성장 목표는 없다.

# 11. 기술 구조와 필수 작동 범위
권장: **Vite + React + TypeScript + Three.js + @react-three/fiber + @react-three/drei + Zustand**, 화면 스타일은 Tailwind 또는 가벼운 CSS. 배포는 Vercel 호환 정적/웹앱 구조로.
- Scene: `World1998`, `Room`, `Alley`, `StationeryShop`, `Playground`, `Garden`.
- Game logic: `PlayerController`, `CharacterRig`, `AnimationStateMachine`, `RubberBandGame`, `RopeSimulation`, `InteractiveProp`, `CameraController`.
- App/UI: 접근 가능한 자막/대화/설정, 모바일 터치 컨트롤, 음악 선반, 방 꾸미기, AI 대화, 물건 기록.
- Data: `Profile`, `MemoryNote`, `DialogueMemory`, `ObjectMemory`, `PropCatalog`, `MusicSelection`, `WorldState`, `PlaySession`.
- 저장은 첫 단계에서 IndexedDB(LocalStorage는 경량 옵션)로 실현하고, 추후 Supabase Auth/Postgres/Storage/Realtime을 연결할 수 있도록 repo/service 어댑터를 분리한다. Supabase 설정이 없을 때 빌드가 실패하지 않게 하라.
- AI는 `AiCompanionAdapter`(실제 API 호출 가능 시 서버 전용 비밀키 사용)와 local demo scripted path를 분리. 공개 브라우저 코드에 비밀키를 넣지 마라.
- 음악은 `MusicProviderAdapter`와 공식 링크. Avatar는 `AvatarGenerationAdapter`와 기본 아바타 수정기.
- 자산 라이선스 README, 개인정보/보존 설정 안내, 모든 민감한 기능의 opt-in.
- 테스트: 빌드+lint+핵심 로직 유닛테스트+가능한 브라우저 E2E. 성능 모니터링, 모바일 프레임 드롭 대비 설정.

# 12. 제작 순서: 문서 작성이 아니라 직접 구현
**우선순위 P0: 실제로 움직이는 3D 버티컬 슬라이스부터 완성하고 검증**한다. 하나의 세션에서 모든 부가 기능이 끝나지 않으면 가장 중요한 플레이 가능 기능을 먼저 만들되, 각 남은 기능은 분명히 미구현이라고 표시하라.

P0 - 반드시 먼저:
1. 새 프로젝트 초기화 / 실행 스크립트.
2. 실제 3D 1998 골목 + 3인칭 캐릭터 이동·카메라·점프·애니메이션.
3. 진짜 3D 고무줄놀이 장면(두 NPC, 탄성 줄, 이동/점프/밟기/걸기/돌기 및 시각적 반응).
4. 1998 방 진입, 오브젝트 하나 이상 실제 3D로 배치/클릭.
5. 고무줄놀이 종료 후 AI 기본 대화 → 사용자가 만든 격려 문장 → '고무줄 상자' 오브젝트에 저장 → 재입장하여 다시 읽기.
6. PC와 모바일 조작, 개발 서버 정상 실행 및 테스트.

P1 - 핵심 세계 확장:
7. 사진 선택/아바타 수정, 기억의 방 ↔ 관심의 방 ↔ 나다운 정원.
8. 소품 카탈로그(최소 20개), 오브젝트 배치/재배치, 추억 메모/목소리 녹음(권한 동의).
9. 음악 선반과 합법적인 외부 음악앱/공식 링크 연결.
10. 첫 AI 온보딩 및 사용자의 승인을 받은 개인화 기억 구조.
11. 문방구 및 땅따먹기·팽이치기의 초기 플레이 가능 구현.

P2 - 실제 온라인 기능:
12. Supabase 등 연동 후 친구 초대·실제 방 생성·실시간 위치/행동 동기화.
13. 안전한 익명 매칭과 신고·차단·연령 보호, 세션 종료.
14. 세이브 동기화, 퍼포먼스 최적화, UX 테스트 후 공개 베타 준비.

# 13. 완료 판정 기준 (실물 동작 검증)
다음 조건을 통과하지 않으면 '완성'이라고 쓰지 마라.
- [ ] 3D 장면을 회전하거나 캐릭터가 이동할 때 원근/위치가 실제로 변함.
- [ ] WASD 입력으로 캐릭터가 걷고 다리·팔 애니메이션이 움직임.
- [ ] Space를 누르면 캐릭터가 실제로 공중에 뛰어오르고 착지함.
- [ ] 고무줄놀이에서 발이 줄을 넘고, 밟고, 거는 움직임이 보이며 줄이 실제로 휘어짐.
- [ ] 사용자 입력 없이 버튼 문구만 전환되는 '가짜 플레이'가 아님.
- [ ] 방 안의 물건이 실제 3D 좌표에 배치되고 저장 뒤 다시 나타남.
- [ ] AI 대화(실제 API 또는 명확히 표기된 로컬 대체모드) 후 사용자가 적은 말이 고무줄 상자에 저장되고 재확인 가능.
- [ ] 사진/AI/음악/멀티플레이 기능이 연결되지 않은 경우 '연결 예정'이라고 명확하게 표시.
- [ ] 앱이 모바일에서 깨지지 않고, 자막/조작/나가기 버튼이 동작함.
- [ ] 실행 명령과 사용된 외부 에셋/라이선스, 구현/미구현 항목이 README에 설명됨.

# 14. Codex 실행 요청
1) 현재 폴더에 프로젝트가 이미 있으면 먼저 검사해 기존 파일을 무단으로 삭제하지 말고, 기존 프로젝트에 통합하거나 안전한 새 디렉터리를 만든다.
2) 위 전체 비전을 간결히 `docs/PRODUCT_VISION.md`, 실제 개발 작업을 `docs/IMPLEMENTATION_PLAN.md`에 문서화하되 **문서만 만들고 끝내지 말라**.
3) 즉시 P0 구현을 시작하고, 필요하면 동작 확인 가능한 범위부터 반복 개발한다.
4) 실행 가능한 프로젝트, 3D 씬, 실제 이동과 고무줄 동작, 조작 설명을 제공한다. 가능하면 자동 테스트와 캡처로 검증한다.
5) 완료 보고는 오직 확인한 사실만: **실제 동작하는 부분 / 아직 모형이거나 미구현인 부분 / 설치 및 실행 명령 / 다음 작업** 순서로 한다. 확인되지 않은 기능을 '구현 완료'라고 쓰지 마라.
6) 내가 원하는 것은 '정서적 경험과 진짜 게임 플레이가 공존하는 따뜻한 1998년 세계'이다. 겉모양만 예쁘게 만드는 것보다 직접 조작과 경험의 완성도를 우선한다.

**지금 파일을 작성하고 로컬에서 실행·테스트하라. 특히 고무줄놀이의 3D 캐릭터 점프·이동·고무줄 반응을 눈에 보이게 구현하라. 구현되지 않은 기능이 있다면 정직하게 표시하라.**
